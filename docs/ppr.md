L'architecture, le découpage du code et la façon dont il est écrit tentent de répondre aux mieux aux risques identifiés suivants :

| Risque et description | Gravité / Impact | Probabilité | Solution apportée |
| --- | --- | --- | --- |
| **Erreur d'unité, valeurs aberrantes** : mauvaise valeur en entrée, gestion silencieuse de valeurs aberrantes / `NaN` dans le code Python. | **Élevée** : fausse mesure, non-conformité d'essai, décision technique erronée, fausse alarme ou alarme manquée. | Moyenne | Découpage modulaire isolant chaque étape du traitement, typage et validation explicite des entrées/sorties, tests unitaires si possible (non obligatoire). |
| **Modification non tracée du code** : changement appliqué sans validation, plusieurs versions dans l'équipe| **Élevée** : perte de traçabilité, impossibilité de rejouer un résultat ou d'identifier un bug. | Faible à Moyenne | Utilisation de Git sur Github |
| **Injection de code malicieux** : exécution par le client ou un opérateur de code altéré ou issu d'un compte compromis sur leur propre machine. Risque de casse du matériel d'étude. | **Critique** : compromission du poste client, atteinte à l'intégrité des systèmes, risque pour la sécurité des opérateurs et responsabilité du bureau d'études. | Faible | Authentification forte (**2FA**) obligatoire sur les comptes Git avec accès en écriture, exigence de **commits signés** ou passage obligatoire par une **Pull Request (PR) avec revue** pour tout commit non signé. |
| **Perte de données** : panne d'un poste local, suppression accidentelle, corruption de disque. | **Élevée** : perte définitive de développements. | Faible à Moyenne | Hébergement centralisé sur serveur Git distant avec **sauvegardes régulières** + au moins une sauvegarde hors site. |
| **Écart d'environnement** : évolution implicite d'une bibliothèque ou différence de version Python entre le poste de développement et le poste d'essai. | **Moyenne à Élevée** : comportement différent sur le terrain, plantage lors du traitement. | Moyenne | Environnements virtuels dédiés et versions de dépendances verrouillées |
| **Exposition de secrets ou d'identifiants** : présence de clés API, mots de passe, jetons d'accès ou chemins sensibles dans le dépôt Git ou les fichiers suivis. | **Élevée** : compromission d'accès, fuite de données techniques ou d'infrastructure. | Faible | Fichier `.gitignore`, externalisation des secrets via fichier `.env` si nécessaire. |
| **Dépendance à une personne** : code, conf ou procédure d'exécution peu documentée ou concentrée sur un poste local. | **Moyenne à Élevée** : blocage d'une campagne d'essais, retard de maintenance ou perte de données en cas d'absence ou de panne matérielle. | Moyenne | Architecture Python modulaire et lisible, `README` d'exploitation (à jour), fichiers de commentaire de développement |
